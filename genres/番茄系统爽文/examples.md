# 番茄系统爽文 — 范例分析

> 示例来自番茄平台热门作品（隐去书名和角色名），仅提取可迁移的技法模式。

## 示例 1：任务流开局

**场景**：主角第一天获得系统，系统发布第一个新手任务。

**处理方式**：
1. 主角不信 → 系统用不可否认的方式证明自己（身体感知/可见变化）
2. 任务内容与当前处境直接关联（不是凭空任务，是帮主角解决眼前的问题）
3. 第一次完成任务的过程展示主角的核心特质（聪明/果断/谨慎/莽撞——决定了全书的性格基调）
4. 奖励不只是给东西，还给了下一个任务的线索

**可迁移技法**：
- 开局任务不要发无关紧要的，要和主角当前最急迫的需求挂钩
- 第一次系统交互 = 确立系统的人设（机械/幽默/高冷）
- 奖励里埋线索 = 让读者期待下一个任务

## 示例 2：打脸场景的见证者设计

**场景**：一直被看不起的主角展现实力。

**处理方式**：
1. 见证者分三层：质疑者（一直在嘲讽）、中立者（围观群众）、知情者（已开始怀疑主角不简单）
2. 打脸时三层人的反应按顺序写：质疑者闭嘴 → 中立者震惊 → 知情者「果然如此」
3. 主角的行为本身不写「震惊全场」——写三层的具体反应

**可迁移技法**：
- 见证者要分层次，不要全员「震惊」
- 最爽的打脸是「对方刚嘲讽完，下一秒就被打脸」
- 反应要有递进：沉默 → 小声议论 → 公开承认

## 示例 3：系统奖励的设计递进

**场景**：主角完成一个困难任务，系统给奖励。

**处理方式**：
1. 先给预期的奖励（读者知道会有的）
2. 再给额外的惊喜（隐藏任务完成/超额完成评分）
3. 最后给一个「隐忧」——新能力有代价/新道具被某人盯上/新权限触发了某个势力的警觉

**可迁移技法**：
- 奖励三段式：预期+惊喜+隐忧
- 隐忧 = 下一章的钩子（如果只有前两段，爽完就没了）
- 不要让奖励全是好事——读者不信，也觉得假

## 示例 4：系统人格的作用

**场景**：主角面临道德困境，系统给出了出人意料的选择。

**处理方式**：
- 系统提示：「检测到宿主犹豫。提示：系统任务不可拒绝。完成方式可选。」
- 机械的系统提示迫使主角自己想方案——系统给规则，不给答案
- 读者在猜：「如果是你，你会怎么选？」

**可迁移技法**：
- 系统给规则不给答案 = 保留主角的主动性
- 系统的「限制」可以成为故事张力来源
- 系统人格一致性：每次出场的语气/态度/方式不能变
