# 迪化流 — 系统面板模板

> **本文件是参考模板，不是某本书的最终面板。** 每本书在 init 时由 Architect 实例化到 `setting/系统面板.md`（锁定为全书唯一权威），写作、检查、校正都只认该书文件。
>
> 迪化流的系统只有一个职责：**提供长期目标和反常识的行为指令**。它不解释误会、不帮主角澄清、不给中间战力。面板越薄越好——误会的戏给场景，不给面板。
>
> 模板里的【结缘百次】只是示例实例化：具体主线任务名、行为题材（相亲/饭局/签单……）、里程碑规则，都由每本书 init 时定制——结构照抄，内容换皮。

## 使用规则

1. **字段克制**：只保留主线进度、里程碑、调味任务三块，能省则省。
2. **格式规范**：遵循 `references/web-novel-formatting.md`——系统文字【】包裹、每字段单独一行、数字半角、进度 `x/y`、面板顶格不缩进。
3. **进度是私密的**：主角查看进度是"没人发现的执念"，除了主角，面板上的数字不应被配角读到。

---

## 主面板（主线进度）

主角查进度、照进度行事时。一次只更新一行数值，不重排字段。

```
【主线任务：结缘百次】
【进度：12/100】
【当前阶段：初识期】
【达成奖励：1000 亿】
```

> "当前阶段"随系统阶段划分变化（初识期 → 择偶期 → 摊牌期 → 终局期），由每本书的系统设计决定，不是必填。

## 里程碑通知

进度达到 N 的整数倍时弹出。奖励入账后即更新主面板。

```
【里程碑达成：相亲 20 次】
【奖励到账：成功人士形象套装 ×1】
【下一里程碑：40 次（解锁：上层圈宴会邀请）】
```

> 里程碑奖励的设计取向：给"能被解读成豪门手笔"的东西（形象、场合、人脉的入场券），而不是属性点数——奖励的意义在于喂养误会。

## 调味任务（阶段出现，极简）

阶段性的小任务，完成给与主线相关的便利。只出现于需要推上一层的章节。

```
【支线任务】
【任务：出席一场高端酒会】
【奖励：婚介所 VIP 资格】
```

> 调味任务的"为什么做"解释权在系统，不在书页里展开。任务发布本身也是一种"外人眼里没法理解的行为"，可当误会燃料，但**不可多用**——主线才是误会主引擎。

## 系统提示

奖励到账、发布任务、写明规则。一行一条。

```
【叮——支线任务完成，奖励已发放】
【主线进度更新：35/100】
【提示：主线任务不可拒绝】
```

> 系统人格只能"机械冷处理"（发通知、记进度、报规则）。它不评价主角、不点评误会、从不说"宿主不必在意他人眼光"——这类人性化台词会抢走配角脑补的戏。

## 反模式（禁止）

- ❌ 面板堆字段（加力量/积分/技能/背包）×——迪化流系统不是 RPG，加了就变味
- ❌ 系统出来澄清误会（"宿主，他们误会你了"）——系统不背锅，误会纯靠主角自己睁眼瞎趟
- ❌ 系统人格嘴碎（调侃/傲娇/点评）——迪化流的喜感来自主角无奈，不来自系统讲段子
- ❌ 进度写成百分比或分数（`12/100` 不要写成 `12%` 或 `十二分之三`）
- ❌ 同一面板多个叫法（一会儿「结缘百次」一会儿「姻缘任务」）
