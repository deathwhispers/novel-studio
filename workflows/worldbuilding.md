# worldbuilding — 世界观构建 Workflow

## 状态机

```
用户: /novel world
            │
            ▼
    Orchestrator: 确认构建范围
            │
            ├── 添加角色 → Architect(角色档案)
            ├── 完善力量体系 → Architect(力量体系)
            ├── 扩展世界观 → Architect(地理/势力/时间线)
            └── 修复设定冲突 → Architect(冲突检测+修复)
            │
            ▼
    StateManager: 同步 character.yaml（如有角色变化）
```

## 构建范围

Orchestrator 确认用户意图后调度：

| 用户说 | 构建范围 | Architect 加载 |
|--------|---------|---------------|
| 「添加一个新角色」 | 创建角色档案 | 已有角色列表 + 品类配方 |
| 「完善力量体系」 | 扩展力量等级/规则 | 已有力量体系 + 品类配方 |
| 「补世界观」 | 地理/势力/时间线 | 已有世界观 + 品类配方 |
| 「设定有冲突」 | 检测+修复 | 全部硬设定 + 已有正文引用 |
| 「看看还有什么缺的」 | 全面审视 | 全部 canon |

## Architect 执行

### 添加角色
```
1. 逐项填写角色档案（id/name/role/archetype/surface/depth/arc/constraints）
2. 如果是 POV 角色 → 额外填写 knowledge 块
3. 检查与已有角色的关系 → 在已有角色档案中补 relationships
4. 写入 setting/characters/<角色名>.yaml
5. 更新 setting/硬设定.yaml（如果新角色引入了新约束）
```

### 完善力量体系
```
1. 读取已有力量体系 + 品类配方
2. 确认要扩展的维度（等级/获取方式/限制/稀有度/社会影响）
3. 逐等级描述能力范围、社会地位、解锁内容
4. 与主角当前等级对齐
```

### 扩展世界观
```
1. 确认扩展维度（地理/势力/历史/文化/经济）
2. 以主角当前位置为中心，向外扩展（不要从世界起源开始）
3. 只创建当前卷会实际用到的内容
4. 不确定的标注「待确认」
```

### 设定冲突检测
```
1. 读取全部硬设定
2. 读取全部角色档案
3. 逐条检查：
   - 角色之间的能力/关系/时间线是否矛盾？
   - 力量体系的等级与角色当前等级是否一致？
   - 地理/时间约束是否合理？
4. 发现冲突 → 标注 + 建议修复方案 → 由用户决定
```

## State Manager 同步

Architect 修改角色档案后：
- 同步 `character.yaml` 中的角色状态（新增characters/更新已有角色）
- 如果修改了硬设定 → 记录变更

## 渐进原则

- **最小可用**：只创建当前卷需要的设定，不为 500 章后的内容预建设定
- **主角中心**：世界观以主角当前的感知范围为边界，不写百科全书
- **可推翻**：未在正文中出现过的设定标注为「未锁定」，可修改
- **已锁定的**：正文中已出现的设定，修改须评估对已写章节的影响

```
⚠️  检测到 1 处潜在冲突：

📋 下一步：/novel write 1 — 开始写第一章
```
