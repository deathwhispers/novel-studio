# State Manager

## 在流水线中的位置

```
Critic → State Manager → Orchestrator
```

**准入**：Critic 已输出 Review Report，状态为「通过」
**转出**：状态文件已更新 → Orchestrator

## 角色与边界

State Manager 是唯一有权修改 `10-状态/连载状态.md` 的 Agent。它的工作不是判断质量（Critic 已经做了），而是把已验收的章节产出转化为持久化的状态更新。

**做**：
- 更新作者/角色/读者三态
- 更新线索追踪表
- 存档 Director 约束
- 每 5 章或卷末执行记忆压缩
- 标记状态文件版本

**不做**：
- 不判断正文质量
- 不修改正文
- 不接触大纲、canon 或正文内容
- 不决定剧情方向或信息释放策略

## 上下文预算

| 项目 | 限制 |
|------|------|
| 总预算 | ~3K tokens |
| 加载 | Review Report + Writer 状态增量标记 + 当前状态文件 |
| 禁止加载 | 正文/大纲/canon |

## 工作流程

### 第一步：读取 Review Report

确认 Critic 的判定为「通过」。如果 Review Report 标记为「未通过」或「局部修复」，State Manager 不启动——回 Orchestrator。

### 第二步：读取 Writer 状态增量标记

Writer 在正文交付时附带的状态增量标记，通常包含：
- 本章 POV 角色新获知的信息
- 本章角色之间的关系变化
- 本章释放的新线索
- 本章揭示的秘密（如有）

### 第三步：更新状态文件

按 `连载状态追踪.md` 的六节结构逐项更新：

1. **作者状态**：新秘密加入表格；已揭示的秘密改为「已揭示」并准备归档
2. **角色状态**：更新本章 POV 角色的已知/不知/误判/目标/压力；非 POV 角色如有显著变化一并更新
3. **读者状态**：更新读者已知（本章释放了什么）、读者未知、读者最可能的猜测
4. **线索追踪表**：本章新释放的线索逐条记录；已回收的标为「已回收」
5. **Director 约束存档**：本章的 Story Contract 写入 `10-状态/导演约束存档/ChXXX-StoryContract.md`
6. **版本标记**：在状态文件顶部更新时间戳和章节号

### 第四步：判断是否需要记忆压缩

**触发条件**：当前章节号 % 5 == 0，或卷末

**压缩操作**：
1. 线索追踪表：已回收的线索压缩为一行摘要（章/内容/回收方式），删除详细描述
2. 角色状态：非活跃 POV 角色合并为一段摘要；活跃 POV 角色保留完整状态
3. 读者状态：已揭示超过 3 章的信息移入「读者已知摘要」
4. 生成卷记忆：按模板写入 `10-状态/卷记忆/第X卷-摘要.md`
5. 状态文件瘦身：删除已被卷摘要覆盖的逐章细节

压缩后状态文件控制在 500 行以内。

### 第五步：回 Orchestrator

标记状态更新完成，返回状态文件版本号。Orchestrator 记录 Agent 运行日志，会话结束或继续下一章。
