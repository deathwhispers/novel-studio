# 因果链检测

## 能力范围

- 检查事件序列是否能用「因为…所以…」连接
- 检测剧情推进中的逻辑跳跃
- 检测角色行为背后的动机缺失

## 检测方法

### 步骤 1：事件链提取

从正文中提取本章的关键事件序列：

```
事件 A（输入/触发）→ 事件 B → 事件 C → … → 事件 N（章尾）
```

每两个相邻事件之间标注因果类型：

| 类型 | 含义 |
|------|------|
| 因果 | B 是 A 的直接后果 |
| 反应 | B 是角色对 A 的反应（基于角色的动机和性格） |
| 巧合 | B 与 A 同时发生但无因果关系 |
| 跳跃 | B 发生在 A 之后但找不到因果链 |

### 步骤 2：因果断裂检测

对每个「跳跃」类型检查：

- [ ] 角色行为是否有动机支撑？
- [ ] 事件发生是否有前文铺垫？
- [ ] 是否有必要的中间步骤被省略？

### 步骤 3：常见因果问题

| 问题 | 例子 | 修复方向 |
|------|------|---------|
| 角色突然做出不符合性格的选择 | 一直谨慎的主角轻信明显陷阱 | 补充动机铺垫或修改行为 |
| 事件无后果 | 一场大战打完，第二天像没事一样 | 每场戏必须改变局面或留下代价 |
| 巧合推动关键剧情 | 重要道具恰好出现在主角路过的地方 | 给巧合加因果链（有人放的/之前埋的） |
| 角色智商忽高忽低 | 反派前面布局周密，最后蠢死 | 主角破局靠能力而非反派降智 |
| 信息获取方式不合理 | 主角「恰好听到」关键信息 | 信息获取要有过程（打听/推理/交易） |

## 输出格式

```yaml
causality_report:
  passed: true/false
  issues:
    - severity: "硬伤"
      location: "场景2→场景3过渡"
      description: "场景2结尾主角右手受伤，场景3开头用右手拔剑"
      fix: "改为左手拔剑，或补充右手已处理的过渡句"
    - severity: "软问题"
      location: "场景1"
      description: "主角得知关键信息的途径是'恰好听到'——巧合感太强"
      fix: "改成主角注意到对方的异常行为，主动跟踪后得知"
```

## 边界判断

以下**不是**因果问题：

| 表达 | 为什么可以 |
|------|-----------|
| 巧合引发次要事件 | 过于完美的巧合才有问题 |
| 角色做出冲动行为 | 前提是冲动符合该角色的一贯性格 |
| 信息不完全对等 | 角色做决策时信息不足是合理的 |
