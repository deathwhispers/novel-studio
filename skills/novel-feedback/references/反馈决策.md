# 反馈决策与写作调整

> 用途：把分析结果变成最小、可执行、可验证的写作调整。
> 适用：已经确认根因，准备决定改哪一章、改什么、怎么验证。

## 一、决策流程

```
反馈数据 → 归因 → 判断影响范围 → 生成最小指令 → 执行 → 验证
```

## 二、归因决策表

| 信号 | 问题类型 | 决策 |
|---|---|---|
| 单章追读突降 < 50% | 单章写法 | 体检并修复该章问题段 |
| 连续 3 章下降 | 节奏型 | 排查近 10 章推进密度 |
| 卷末大跌 | 卷末钩子 | 重设卷末钩子 |
| 开卷低 | 商业化 | 重审书名/简介/开篇 |
| 整体缓慢下滑 | 结构性问题 | 卷体检 + 调整节奏型 |
| 断崖下跌 | 重大失误 | 定位问题章并修复 |

| 评论集中反馈 | 根因 | 决策 |
|---|---|---|
| "节奏慢""水" | 推进段无实质冲突 | 压缩铺垫或加冲突 |
| "看不懂" | 信息释放不当 | 放慢信息节奏或加提醒 |
| "太套路" | 技法重复 | 换核心技法 |
| "感情线拖/太快" | 关系推进失衡 | 补推进或补过渡 |
| "反派太蠢" | 反派无自身逻辑 | 重写反派决策依据 |
| "主角圣母" | 代价不足 | 补内心代价或约束 |
| "挖了不填" | 伏笔回收过慢 | 加速回收或增加提醒 |
| "设定崩了" | 规则被打破 | 修复一致性 |

## 三、优先级

| 级别 | 条件 | 响应 |
|---|---|---|
| P0 | 追读 < 40% 或大量弃书 | 24 小时内处理 |
| P1 | 连续 3 章下降或集中骂某类问题 | 3 天内处理 |
| P2 | 缓慢下降或个别负面评论 | 观察或微调 |
| P3 | 趋势稳定或正面反馈 | 记录，不干预 |

## 四、写作指令对照

| 反馈 | 指令示例 |
|---|---|
| 节奏慢 | 下一章推进段必须有实质冲突，不是"准备出发"而是"出发时遇到意外" |
| 太赶/看不懂 | 一次只放 1 个新信息，增加必要的提醒 |
| 套路重复 | 上一章用反转，这一章改信息差或代价推进 |
| 主角太蠢 | 主角决策必须有信息差或压力约束支撑 |
| 配角无存在感 | 给配角 1 个独立目标与动作 |
| 感情线拖 | 下一章安排 1 次关系推进事件 |
| 设定崩 | 先遵守已建立规则，再用场景展示修正 |

## 五、决策输出模板

```markdown
## 反馈决策 #FB-{{日期}}-{{序号}}

- 触发：{{追读跌/读者骂/用户请求}}
- 数据来源：{{章节范围/评论数量/具体指标}}
- 根因：{{问题根因}}
- 影响范围：{{章节/卷/全书}}
- 指令：{{改什么/怎么改}}
- 预期效果：{{读者反应或数据变化}}
- 验证方式：{{发布后多久检查什么}}
- 执行 skill：{{novel-outline/novel-writing/novel-worldbuilding/novel-market}}
```

## 六、执行与验证

| 决策类型 | 执行路径 |
|---|---|
| 改单章问题段 | novel-quality → novel-writing |
| 改节拍卡/章尾钩子 | novel-outline → novel-writing |
| 改卷方向 | novel-outline → novel-worldbuilding/novel-writing |
| 改角色弧线 | novel-worldbuilding → novel-outline → novel-writing |

执行后必须验证：

1. 是否引入新问题或破坏连续性？
2. 发布后 24-48 小时看追读是否变化。
3. 3 天内看同类评论是否减少。
4. 在 `90-运行/决策记录.md` 记录触发、根因、决策、执行和验证结果。

## 七、纪律

- 反馈是信号，不是命令；先归因，再决定。
- 一次只改 1-2 个变量，不凭单条评论改主线。
- 追读上升也要记录原因，不只处理负面反馈。
- 改了必须验证；不验证等于无效决策。
- 早期章节样本太少，不启动大范围改写。

## 八、快速检查

1. 当前最严重问题的根因是什么？
2. 下一章只需改哪 1-2 件事？
3. 怎么判断这次调整有效？

说不清，回到 `反馈分析.md`。
