## 一、输出格式

向其他 skill 输出时使用以下格式：

```markdown
## 反馈指令 #FB-{{日期}}-{{序号}}

### 来源
- 触发：{{追读跌/读者骂/用户请求}}
- 数据支撑：{{具体数据}}
- 分析依据：`novel-feedback/references/反馈分析.md`

### 问题诊断
- 问题类型：{{节奏/角色/感情/设定/其他}}
- 影响范围：{{章节/卷/全书}}
- 严重程度：{{P0/P1/P2/P3}}
- 根因：{{一句可验证的判断}}

### 输出指令
- 目标 skill：{{novel-outline/novel-writing/novel-worldbuilding/novel-market}}
- 指令内容：{{改哪部分、改成什么、不做什么}}
- 预期效果：{{读者反应或数据变化}}
- 验证方式：{{检查时间与指标}}

### 关联文件
- 决策记录：`novel-feedback/references/反馈决策.md`
- 目标 skill 资料：{{对应 skill 的 references/具体文件.md}}
```

## 二、目标 skill 与资料映射

| 反馈指向 | 目标 skill | 常用资料 |
|---|---|---|
| 卷节奏/信息释放/伏笔 | novel-outline | `novel-outline/references/卷级节奏型模板.md`、`信息释放节奏.md` |
| 单章写法/人物动作/对话 | novel-writing | `novel-writing/references/写作技法库/对话写作技法.md` |
| 设定一致性/角色弧线 | novel-worldbuilding | `novel-worldbuilding/references/角色关系网络.md`、`一致性检查清单.md` |
| 市场定位/差异化 | novel-market | `novel-market/references/形式矩阵.md` |

示例：

```markdown
## 反馈指令 #FB-2026-0807-001

### 来源
- 触发：Ch42 追读率从 72% 跌至 55%
- 数据支撑：Ch40-Ch42 连续下降，8 条评论出现"节奏慢"

### 问题诊断
- 问题类型：节奏
- 影响范围：Ch42
- 严重程度：P1
- 根因：推进段只有事件铺垫，没有改变主角处境

### 输出指令
- 目标 skill：novel-writing
- 指令内容：把 Ch42 的"准备出发"改成"出发时遭遇意外"，保留原有后果
- 预期效果：Ch43 追读率回升到 65% 以上
- 验证方式：发布后 48 小时对比 Ch42/Ch43 追读率

### 关联文件
- 决策记录：`novel-feedback/references/反馈决策.md`
- 目标 skill 资料：`novel-writing/references/写中即时检查卡.md`
```

## 三、指令消费规范

收到 `novel-feedback` 的指令后：

1. 先读决策记录，确认根因和证据。
2. 评估指令是否与当前规划冲突，冲突时反馈而不是照单全收。
3. 执行后说明改了/没改/为什么。
4. 按约定时间回看数据或评论。

---

## 四、协作纪律

- `novel-feedback` 只给方向和范围，不替目标 skill 决定具体文字。
- 其他 skill 不忽略反馈，但可以质疑归因和可行性。
- 冲突时以多章数据和集中评论为准，不以单条极端反馈为准。
- 每条指令都要闭环：发出 → 执行 → 验证 → 记录。

---

## 快速检查

1. 反馈分析完后，应该向哪个 skill 输出指令？
2. 指令中是否包含：改什么/怎么改/预期效果/验证方式？
3. 目标 skill 收到指令后，是否知道该参考哪些文件？

任一题"否"，指令不合格，需要重写。
