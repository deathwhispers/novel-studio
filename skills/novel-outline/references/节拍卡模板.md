# 节拍卡范例片段

> 用途：为商业连载或类型长篇的当前章节提供最小写作支点。按需创建，不是每章必填 10 项；文学、短篇和探索起草可以直接写几行当前任务。
> 文件：`20-大纲/节拍卡/chapter-XXX.md`，也可以在正文前只给出支点。

## 最小结构

```markdown
# 第 {{XXX}} 章：{{章节名}}

- 视角人物：{{姓名}}（为什么选这个视角：{{信息差}}）
- 核心戏剧任务：{{人物}}必须{{动作}}，因为{{被什么逼}}，但{{被什么卡住}}
- 因果锚点：上一章 {{结果}}，所以本章 {{被迫做的事}}
- 阻力：{{具体的人 / 规则 / 环境 / 信息差}}
- 局面变化：章初 {{状态}} → 章末 {{状态}}
- 章尾作用：推动 / 余震 / 回响 / 悬念 / 留白
- 待确认或继承：{{下一段必须继承什么}}
```

## 合格示例

```markdown
# 第 3 章：雨先落进门里

- 视角人物：沈砚（他知道欠债真相，妹妹不知道）
- 核心戏剧任务：沈砚必须把债主挡在妹妹察觉之外，因为债主明天上门，但他不能让妹妹知道母亲欠债。
- 因果锚点：上一章妹妹从钱袋起疑，所以本章沈砚要抢先处理债务。
- 阻力：债主掌握欠条，妹妹正在靠近谈话地点。
- 局面变化：沈砚以为能继续隐瞒 → 债主当面点破妹妹的存在。
- 章尾作用：推动下一章选择——让妹妹留下还是送她离开。
- 待确认：债主和沈砚过去是否有私人恩怨。
```

## 常见戏剧任务原型

| 原型 | 一句话定义 | 阻力设计 |
|------|-----------|----------|
| 获取 | 得到某物或某信息 | 有人在抢先、阻止或误导 |
| 逃离 | 离开某地或状态 | 出口被封、追捕者或内心犹豫 |
| 守护 | 保护某人或某物 | 保护对象不配合、多方威胁或需要牺牲 |
| 揭示 | 让某人知道真相 | 对方不信、误解或时机不对 |
| 说服 | 让某人改变立场 | 利益冲突、把柄或信任缺口 |
| 牺牲 | 放弃重要的人、物或原则 | 代价太大、替代方案更危险或他人阻止 |

单一任务撑不住时，可以组合两个原型，例如“获取 + 守护”或“说服 + 牺牲”。

## 本章信息边界

> 大纲知道全部，但本章只能释放部分。不设边界 = AI 会用上帝视角写作，提前暴露隐藏线。

| 层级 | 内容 | 说明 |
|------|------|------|
| 可释放 | | 本章读者应该知道的新信息 |
| 可暗示 | | 本章可以用模糊方式提及，但不点明（让细心读者自己发现） |
| 禁止触碰 | | AI 知道但本章绝对不能写——隐藏身份、未公开伏笔真意、后续反转、尚未揭露的规则 |

### 信息边界自检

- 视角人物在本章有理由知道这些禁止信息吗？没有 → 正文中绝不能出现
- 如果读者读完本章、回看时能发现某个细节是伏笔 → OK（暗示层）
- 如果读者读完本章就能明确猜出某个后续反转 → 泄漏（不可接受）
- 叙述者的语调和判断是否超过了视角人物的认知？→ 如果是，修改视角或切叙述距离

## 跨章衔接检查

- 上一章的结果是否把本章逼出来？
- 本章的局面变化是否会在下一章产生后果？
- 本章释放的信息是否制造了新问题？
- 旧线和伏笔只在实际追踪时维护，不要求每章都新增一条。

## 常见错误

| 错误 | 表现 | 修复 |
|------|------|------|
| 任务太泛 | “推进剧情” | 换成具体动作和被逼/被卡结构 |
| 阻力空泛 | “很难”“有危险” | 换成具体的人、规则、环境或信息差 |
| 变化可逆 | “差点被发现” | 变成已发生的状态，如“已经被发现” |
| 章尾没有作用 | 停在总结 | 明确推动、余震、回响、悬念或留白 |
| 为填卡而填卡 | 把所有字段写满但任务不清 | 只保留能支撑下一章写作的字段 |

## 快速检查

1. 为什么由这个视角人物看这一章？
2. 人物被什么逼、又被什么卡住？
3. 章末读者最关心的问题是什么？

答不清楚时补对应部分，答清楚就可以进入 `novel-writing`。
