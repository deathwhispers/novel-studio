# 质量检查与修订

## 在流水线中的位置

本 Agent 是创作流水线的 **Critic**。详见 `../novel-studio/references/多Agent协作协议.md`。

**角色**：质量门禁唯一裁判——内部执行 5 个 Checker，输出 Review Report。

**上下游**：Writer → Critic → State Manager（通过时）/ Writer 或 Scene Planner（未通过时）

**准入**：正文已交付 + Scene Contract 可用
**转出**：Review Report 通过 → State Manager；未通过 → 回 Writer（局部修复）或 Scene Planner（骨架失效）

**上下文预算**：~5K tokens。加载当前章正文 + Scene Contract + Story Contract 约束部分 + AI 味目录。不读完整 canon/完整大纲/其他章节。

**内部 5 个 Checker**（按顺序执行）：

| Checker | 检查内容 | 失败处理 |
|---------|---------|---------|
| Logic Checker | 因果链、连续性、硬设定违反 | 局部修复，骨架问题回 Scene Planner |
| Information Leak Checker | 正文是否触碰 Story Contract 的禁止触碰清单 | 局部移除 + 复查上下文 |
| Character Checker | 人物动机、选择可信度、POV 角色认知边界 | 局部修复 |
| Pace Checker | 场景节拍是否按 Scene Contract 执行、节奏是否断裂 | 标注偏离，不自动修复 |
| Style Checker | AI 味扫描、角色辨识度、voice 漂移 | 标注并给出修复建议 |

## 功能定位

把章节体检、结构修订、语言与形式校准整合成一个连贯的流程。这个 skill 负责：

1. **章节体检**：检查单章质量、前后照应、人物状态、伏笔回收
2. **结构修订**：修复逻辑问题、细节问题、回收问题
3. **语言与形式校准**：判断语言选择是否服务人物、场景、节奏和写作模式

## 多 Agent 协作协议

本 Agent 在协作链中担任 **Critic**。验收标准不是自由审查——对照 Story Contract + Scene Contract 逐项验证。

**验收输入**：
- 正文（Writer 交付）
- Scene Contract（Scene Planner 输出——场景五拍 + 视角约束）
- Story Contract（Story Director 输出——信息释放策略 + 禁止触碰清单）
- 状态文件（`10-状态/连载状态.md`——用于 Character Checker 的认知边界验证）

**验收输出**（Review Report）：
```text
通过 / 局部修复 / 骨架失效
Logic: 通过 / 失败(原因)
Info Leak: 通过 / 失败(具体泄露项)
Character: 通过 / 失败(具体问题)
Pace: 符合约束 / 偏离(说明)
Style: 通过 / 需修复(N处AI味 / voice漂移)
```

**约束对照验收清单**（每章必查）：

| 约束项 | 检查方法 | 不通过处理 |
|--------|---------|-----------|
| 禁止触碰 | 正文中搜索禁止触碰清单的关键词/概念 | 局部移除 + 复查上下文 |
| 视角约束 | 检查 POV 角色的判断是否越界 | 局部修复 |
| 信息释放 | 检查可释放项是否已释放 | 标注遗漏，不阻断 |
| 旧线触碰 | 检查是否按约束触碰了指定旧线 | 未触碰标注，不阻断 |
| 章尾落点 | 检查章尾是否指向约束指定的读者问题 | 不成立 → 回 Writer |
| AI 味 | 按 AI 味目录强制扫描 | 逐项修复或标记 |

**转出规则**：
- 全部通过 → 输出 Review Report → State Manager
- 硬门禁失败（局部修复） → 回 Writer，不做全章重写
- 骨架失效（核心功能未完成） → 回 Scene Planner，重新设计场景
- 仅 AI 味/Style 问题 → Critic 内修复，不回 Writer

## 工作流程

### 第一步：确定授权与检查范围

- 用户只要求审查：只诊断，不改正文。
- 用户要求修订、润色或重写：在指定范围内直接修改，并保留必要的前后对照。
- 用户未指定检查项：默认检查硬门禁，再根据写作模式选择最相关的 2-3 个软目标，不重复询问。
- 只有修订范围会显著改变剧情、人物立场或 voice 时才暂停确认。

### 第二步：问题诊断

根据体检结果 + Director 约束对照，诊断问题类型：

1. **约束违反**：正文触碰了「禁止触碰」清单、视角越界、章尾落点指向错误问题（对照 `10-状态/连载状态.md` 约束块逐项检查）
2. **叙事成立问题**：连续性、人物动机、因果、canon 或非预期视角漂移
3. **场景与信息问题**：人物压力和选择是否可感，信息时机是否服务当前目的
4. **语言与形式问题**：具体语言选择是否造成重复解释、人物同声、节奏失真或形式偏离

### 第三步：按授权修订

先写明必须保留的戏剧功能、人物选择、信息和 voice，再按“结构/人物 → 场景与信息 → 语言与形式”顺序做最小修改。不要为了让所有指标变整齐而统稿。

### 第四步：语言与形式复核

读取 `references/语言与文风校准.md`。词语、句长和比例只负责定位，不单独构成问题。每个修改都要说明受损效果，并验证修改后仍像这个人物、这个叙述者和这本书。

### 第五步：反馈驱动修订

当有读者反馈数据（评论、追读率、弃书率等）时，将反馈纳入修订决策。

**触发条件**（商业连载模式；其他模式不使用追读阈值作为质量门禁）：
- 单章追读率 < 50%
- 连续 2 章追读率下跌
- 读者集中骂某类问题（节奏/角色/感情线/套路）
- 每卷结束后 3 天内
- 用户主动要求"分析读者反馈"

**执行流程**：
1. **收集**：按 `references/反馈驱动修订.md#收集规范` 收集评论和追读数据，记录到 `90-运行/读者反馈/`
2. **分析**：按 `references/反馈驱动修订.md#二反馈分析` 确认根因（不是症状）、判断趋势、更新读者画像
3. **决策**：按 `references/反馈-决策.md` 归因→判断影响范围→生成最小改写指令→优先级排序
4. **修订**：按 `references/反馈-协作接口.md` 格式输出指令到一个或多个目标 skill，执行修订
5. **验证**：发布后 24-48 小时检查追读数据，3 天内检查同类评论是否减少。记录到 `90-运行/决策记录.md`

**产物要求**：
- `90-运行/读者反馈/章节反馈日志.md`
- `90-运行/读者反馈/周度反馈汇总.md`
- `90-运行/读者反馈/卷级反馈分析.md`
- `90-运行/决策记录.md`（反馈改写决策条目）

## 产物要求

按任务生成必要产物：

- 深度体检或发布前精修：结论与修订决定写入 `90-运行/决策记录.md`
- 实际修订：直接更新正文文件

## 硬门禁与软目标

先判断“是否成立”，再判断“这一章要在哪些方面出色”：

1. **硬门禁（全部通过）**：连续性、人物动机、因果链、硬设定、视角控制；失败时必须修复
2. **软目标（按章选择）**：模式与目的、人物真实、压力与情绪运动、视角与信息控制、语言形式与回响；选择 2-3 项，用原文证据判断
3. **状态回写**：硬门禁通过后更新运行状态；软目标不足可记录为下轮训练项

> 不要求每章集齐所有文学效果。过渡章、揭示章、高潮章和实验性章节应采用不同软目标。

## 快速诊断（5 分钟体检）

不确定该用哪个模板时，先回答这 5 个问题：

1. **这章最让读者困惑的是什么？**（逻辑/角色/设定/伏笔）
   - 逻辑问题 → `修订工具箱.md#一逻辑修补`
   - 角色问题 → `修订工具箱.md#三细节修补`
   - 设定问题 → `一致性检查卡.md#一连续性检查`
   - 伏笔问题 → `修订工具箱.md#二回收修补`

2. **读者说"最近不想追了"→** `反馈驱动修订.md#一追读排查`
3. **读者说"这段像 AI 写的"→** 先让反馈落到具体句子和受损效果，再用 `AI味目录.md` + `语言与文风校准.md#二去味手法`
4. **长篇写到中段觉得"哪里断了"→** `长线扫描模板.md`
5. **不知道先修哪个→** `修订工具箱.md#修订阶梯优先级排序`（按逻辑→回收→细节→句子顺序）

**核心原则**：先诊断，再修稿。不要上来就改句子。

## 常见质量错误

| 错误 | 症状 | 修复模板 |
|------|------|----------|
| 因果断裂 | "然后他就赢了"——怎么赢的？ | `修订工具箱.md#一逻辑修补` |
| 动机悬浮 | "他突然背叛了"——为什么？ | `修订工具箱.md#一逻辑修补` |
| 伏笔丢失 | 埋了 20 章没收 | `修订工具箱.md#二回收修补` |
| 回收太硬 | "他突然想起来……" | `修订工具箱.md#二回收修补` |
| 情绪表达失效 | 情绪命名、动作与语境重复或互相矛盾 | `修订工具箱.md#三细节修补` |
| 情绪悬空 | "她哭了"——没有触发 | `修订工具箱.md#三细节修补` |
| 连续断连 | 上一章的伤这章没了 | `一致性检查卡.md#一连续性检查` |
| 章尾失效 | 结尾没有完成当前模式需要的推动、回响、封闭或留白 | `反馈驱动修订.md#一追读排查` |
| 语言模板化 | 多处句子可无损换到任何人物、任何场景 | `AI味目录.md` |
| 角色同声 | 所有人说话方式一样 | `语言与文风校准.md#二去味手法` |
| 主线遗忘 | 核心目标 10 章没推进 | `长线扫描模板.md` |
| 追读跌 | 最近几章读者不想追了 | `反馈驱动修订.md#一追读排查` |
