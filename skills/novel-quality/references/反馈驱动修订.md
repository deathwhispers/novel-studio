# 反馈驱动修订

> 用途：从追读数据和评论反馈中收集、定位写作问题，归因并生成修订指令。

---

## 收集规范


> 用途：把零散评论和后台数据整理成可比较的反馈库。
> 适用：每次发布后、每周和每卷收束时。

## 一、收集来源

| 来源 | 实时性 | 记录方式 | 优先级 |
|---|---|---|---|
| 章评/段评 | 实时 | 复制原文并关联章节 | P0 |
| 后台数据 | 延迟 | 导出追读、读完、弃书数据 | P0 |
| 书评 | 延迟 | 记录链接 + 摘要 | P1 |
| 社交媒体/读者群 | 实时 | 记录关键词和典型原文 | P2 |

## 二、评论分类

| 类型 | 标志词 | 处理 |
|---|---|---|
| 夸 | "好看""爽""燃""甜" | 记录具体做对了什么 |
| 骂 | "烂""水""毒""弃" | 记录具体骂什么 |
| 建议 | "建议""如果""不如" | 评估可行性 |
| 讨论 | "是不是""为什么""伏笔" | 看读者理解程度 |
| 催更 | "快更""等不及" | 维持更新节奏 |
| 困惑 | "看不懂""谁是谁" | 标记信息释放问题 |

每条评论至少记录：章节、日期、类型、关键词、情感分（-5 到 +5）、1-2 句原文摘要、读者属性、影响范围。

## 三、追读指标

| 指标 | 定义 | 健康阈值 |
|---|---|---|
| 追读率 | 下章阅读人数 / 上章阅读人数 | 合格 > 50%，优秀 > 70% |
| 读完率 | 完读人数 / 点击人数 | 合格 > 60% |
| 弃书率 | 弃书人数 / 上章阅读人数 | 危险 > 30% |

## 四、记录频率

| 时段 | 动作 |
|---|---|
| 发布后 1 小时 | 快速浏览评论，标记异常 |
| 每天 | 收集当天评论 |
| 每周 | 汇总评论、追读和关键词 |
| 每卷 | 汇总卷级反馈，更新读者画像依据 |

## 五、章节级记录表

```markdown
| 章节 | 日期 | 评论数 | 情感均分 | 关键词 TOP3 | 追读率 | 读完率 | 弃书率 | 行动项 |
|---|---|---|---|---|---|---|---|---|
| Ch 1 | | | | | | | | |
```

周度和卷级汇总可复用同一张表，按周/卷替换粒度。每月额外记录关键词 TOP10，以及读者对核心承诺的期待度与兑现风险。

## 六、快速检查

1. 最近一周的评论数和追读率是否都有记录？
2. 最近 20 条评论的夸/骂比例能否回答？
3. 每章是否关联了具体反馈？

答不上来，先补齐收集，再进入分析。

## 常见追读杀手

| 杀手 | 表现 | 修复 |
|------|------|------|
| **说明章** | 整章都在交代背景/设定/世界观 | 拆成多个小信息包，混入剧情 |
| **回忆章** | 整章都是回忆，没有当下剧情 | 回忆必须影响当下决定 |
| **过渡章** | 主角"准备出发"一整章 | 压缩到半章，另一半推进 |
| **重复章** | 和前几章做同样的事（升级/战斗） | 改变任务类型或增加意外 |
| **平静章** | 章尾没有钩子，主角休息 | 即使是过渡章也要有 ★ 钩子 |
| **信息 dump** | 一章放出太多新信息 | 拆成 2-3 章，每章 1-2 个新信息 |
| **关系冻住** | 关键关系 5 章没进展 | 加关系推进事件 |
| **升级疲劳** | 连续 3 章都是"主角变强" | 引入非能力升级（心理/关系/地位） |

## 快速检查（2 分钟）

最近 3 章：
1. 每章章尾有钩子吗？（★ 以上）
2. 有连续 2 章是同一类型吗？（战斗/对话/说明）
3. 最值钱的读点最近被碰了吗？
4. 主角最近有主动决定吗？

**任一题"否"→进入追读弱点排查**

## 二、反馈分析


> 用途：从评论和追读数据中确认真实问题，不凭单条评论下结论。
> 适用：追踪数据达到样本量后，或用户要求分析反馈时。

## 一、情感与诉求

给每条评论打 -5 到 +5 分，并提取诉求：

| 诉求 | 标志词 | 检查方向 |
|---|---|---|
| 求爽 | "打脸""爽" | 爽点密度与兑现 |
| 求推进 | "别拖""水" | 推进段效率 |
| 求揭秘 | "真相""为什么" | 信息释放节奏 |
| 求感情 | "甜""虐""CP" | 感情线进度 |
| 求角色 | "工具人""主角" | 角色弧线 |
| 求设定 | "规则""看不懂" | 设定释放方式 |

单章情感均分高于 +2 表示维持；0 到 +2 微调；-2 到 0 关注；低于 -2 进入决策。

## 二、趋势判断

画出最近 5-10 章的追读率，先判断形态，再结合评论归因：

| 趋势 | 含义 | 优先检查 |
|---|---|---|
| 稳步上升 | 当前策略有效 | 记录成功因素 |
| 平稳 | 稳定但可能缺突破 | 读点与惊喜 |
| 缓慢下降 | 慢性流失 | 近 10 章推进密度、套路重复 |
| 波动震荡 | 质量不稳定 | 波峰/波谷章差异、更新频率 |
| 断崖下跌 | 节点性事故 | 问题章内容、更新状态、外部因素 |

下降位置也有不同含义：开卷低查书名/简介/开篇；单章跌查该章写法；中段跌查推进密度；卷末跌查卷末钩子；整体跌查卷方向。

数据与评论必须互相印证。例如缓慢下降 + "水""拖" → 推进效率低；断崖 + "毒""弃了" → 重大剧情失误；波动 + "时好时坏" → 质量下限不稳定。

## 三、读者画像

每卷或每 5 万反馈样本更新一次原始画像，只看实际证据：

- 评论中的读者自称、语言风格和常用梗
- 阅读时段、付费行为和活跃平台
- 哪类章节追读最高
- 原画像与实际读者的偏差

画像变化要落到写作调整：读者偏年轻就降复杂度、加快节奏；女性读者增加就补感情线推进；碎片化阅读就降低每章上下文依赖。

## 四、反馈-章节关联矩阵

把最近 10 章设为列，把反馈类型设为行，格内用 ★ 标影响强度。

```markdown
| 反馈类型 \ 章节 | Ch40 | Ch41 | Ch42 | Ch43 | Ch44 | Ch45 |
|---|---|---|---|---|---|---|
| 节奏慢 | | | ★★ | ★★★ | ★★ | |
| 角色降智 | | ★ | | ★★ | | |
| 章尾弱 | ★ | | ★ | | | ★★ |
```

- 列最密：该章是问题核心。
- 行跨多列：这是节奏型或结构性问题，不是单章问题。
- 修复后对应格强度应下降，否则归因错误。
