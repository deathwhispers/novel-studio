# 节奏分析

## 能力范围

- 检查场景字数分配是否符合功能需要
- 检测连续同情绪段落
- 评估章尾翻页动力

## 检测方法

### 步骤 1：场景字数分析

对比 Scene Contract 的 `word_budget_per_scene` 与实际产出：

| 偏差 | 风险评估 |
|------|---------|
| ±10% | 正常波动 |
| ±10-30% | 检查功能是否达成 |
| ±30%+ | 场景可能偏离设计意图 |

### 步骤 2：情绪节奏检测

将正文切为段落单元，标注每单元的主要情绪：

```
段落 1-3: 好奇（主角收到不明任务）
段落 4-7: 紧张（任务比预想危险）
段落 8-10: 紧张（危险升级）
段落 11-12: 紧张（勉强化解）
段落 13-14: 爽感（任务奖励）
段落 15: 好奇（新线索出现）
```

**问题检测**：
- [ ] 连续 5 段以上同一情绪 → 读者可能疲劳
- [ ] 只有一种情绪贯穿全章 → 节奏单调
- [ ] 情绪转换无过渡（突然从搞笑切到悲情，毫无铺垫）

### 步骤 3：章尾动力检测

读取章尾最后 200 字，判断是否能产生翻页动力：

| 动力级别 | 判断标准 |
|---------|---------|
| 强 | 读者脑中有一个具体的、急于得到答案的问题 |
| 中 | 读者好奇但不急切 |
| 弱 | 读者可以停下来，不急着看下一章 |
| 无 | 自然结束——吃饭、睡觉、收工 |

### 步骤 4：节奏断裂检测

- [ ] 该快的地方是否拖了？（关键冲突场景字数明显少于铺垫场景）
- [ ] 高潮是否来得太突然？（缺少加压过程）
- [ ] 过渡是否太匆忙？（两个重要场景之间没有呼吸空间）
- [ ] 是否有明显的空转段落？（删了对前后无影响）

```yaml
    emotion_variety: "2种（紧张+爽感）——够用"

    - scene: 2
      description: "冲突升级太快——读者来不及紧张已经解决"

```

## 边界判断

节奏快慢不是绝对的对错，而是「是否符合场景功能」：
- 过渡场景可以慢一些
- 高潮场景必须紧凑
- 品类配方有节奏基线时与基线对比
