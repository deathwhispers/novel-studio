# 信息泄漏检测

## 能力范围

- 检测正文是否触碰了 `forbid_touch` 清单
- 检测上帝视角叙述（POV 角色不可能知道的信息）
- 检测作者附身（旁白跳出来解释设定或人物心理）

## 检测方法

### 步骤 1：禁止清单逐一搜索

对 `forbid_touch` 中的每一项：
1. 提取关键词
2. 在正文中搜索该关键词及同义表达
3. 检查出现在哪些段落

```
禁止项：「系统的真正来源」
搜索关键词：「系统来源」「系统起源」「谁创造了系统」「系统为什么存在」「系统从哪来」
```

### 步骤 2：上帝视角检测

搜索以下句式（这些句式暗示了超出 POV 角色认知的叙述者）：

| 句式 | 示例 | 为什么是泄漏 |
|------|------|-------------|
| 「他不知道…」 | 「他不知道这将改变他的一生」 | 谁在知道？ |
| 「如果他知道…」 | 「如果他知道了真相」 | POV 之外的信息 |
| 「这将是…」 | 「这将是他们最后一次见面」 | 来自未来的视角 |
| 「后来…」 | 「后来发生的事证明他错了」 | 时间跳跃视角 |
| 「与此同时…」 | 「与此同时，在千里之外…」 | POV 角色无法感知 |

### 步骤 3：作者附身检测

搜索以下模式：
- 旁白解释角色动机（「他这样做是因为…」）
- 旁白评价剧情（「这就是命运的安排」）
- 旁白总结主题（「也许这就是成长的代价」）
- 旁白补充设定（「在这个世界里，XX意味着YY」）

## 输出格式

```yaml
info_leak_report:
  passed: true/false
  leaks:
    - severity: "泄漏"          # 泄漏 | 暗示（边界模糊）
      location: "第4段"
      forbidden_item: "系统的真正来源"
      actual_text: "这个伴随了他三年的系统，其实是…"
      fix: "删除整句。此信息在第50章揭示。"
    - severity: "上帝视角"
      location: "第9段"
      actual_text: "他还不知道，这句话将在三天后成为现实"
      fix: "删除。改为角色当下的判断或怀疑。"
    - severity: "作者附身"
      location: "第15段"
      actual_text: "命运再次证明，所有的捷径都有代价"
      fix: "删除。让事件本身说话。"
```

## 边界判断

以下情况**不算**信息泄漏：

| 表达 | 为什么可以 |
|------|-----------|
| 「他想，也许XX是YY」 | 角色在推断，不是作者在说 |
| 「上次他们见面是三年前」 | 角色在回忆 |
| 「按照规则，XX意味着YY」 | 角色已知的规则 |
| 「他不知道她在想什么」 | 写的是「不知道」，不是「知道」 |
