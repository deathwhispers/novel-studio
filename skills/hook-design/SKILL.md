# 钩子设计

## 能力范围

- 章首钩子（前500字抓住读者）
- 章中钓胃口（让读者在章的任意位置停下来都有一个未解答的问题）

章尾动力不属于本 skill——它是情绪兑现的一部分，见 `skills/emotion-payoff/SKILL.md`「章尾动力」。

## 章首钩子

### 五种有效开局

| 开局类型 | 怎么用 | 示例 |
|---------|--------|------|
| 异常开局 | 展示一个不应该出现在这里的细节 | 「系统第三次弹出同一个任务。他已经完成两次了。」 |
| 悬念开局 | 抛出一个认知缺口 | 「她没有敲门。三年没见，她还是没学会敲门。」 |
| 动作开局 | 从冲突中间开始 | 「刀离他的脖子还有三寸。」 |
| 声音开局 | 用一句有力的对话开始 | 「'你根本不知道你激活了什么。'」 |
| 情绪开局 | 用角色强烈的内心状态开始 | 「他第一次希望系统是假的。」 |

### 章首禁忌
- 不重述前文（读者知道上一章发生了什么）
- 不从起床/出门/到达开始（除非这个日常动作本身有异常）
- 不从环境描写开始（除非环境本身就是冲突来源）

### 章首失败模式（NEW-W4 修复补充）

5 种常见的失败开局——读者 200 字内就会弃章：

| 失败模式 | 表现 | 修复 |
|---------|------|------|
| **白描环境开场** | "清晨的阳光透过窗帘" / "夜幕降临，城市灯火通明" | 直接跳到与角色相关的异常——「系统第七次弹出同一个任务。他已经完成六次了。」 |
| **重述前章** | "上一章主角发现了系统秘密" | 不重述。从上次结尾的下一瞬间开始——读者记得 |
| **状态总结开场** | "李寻欢是个杀手，今年三十五岁" | 人物档案不是开场。在动作中带出来——「三十五岁那年他决定不再杀人。」 |
| **背景铺垫开场** | "三百年前，修仙界与魔族大战" | 直接进当前场景。世界观放在对话/动作里自然带出 |
| **天气开场** | "那天下着大雨" / "阳光明媚的春日" | 除非天气本身就是冲突（暴雨导致主角被困），否则删 |

**自检**：写完章首 200 字，问 3 个问题：
- [ ] 读者 30 秒内知道本章要发生什么吗？
- [ ] 有没有不重述前章？有没有不让读者跳过？
- [ ] 章首 200 字是否有动作/异常/对话/情绪——而非环境铺垫？

## 章中钓胃口

### 技法一：给线索但不给准

给出线索让读者自己补全——然后用读者想不到的方式兑现：
- 给出部分线索（「关于这里，传闻很多」——不说是哪些传闻）
- 暗示方向但不确认（「也许是A……但也可能是B」）
- 让线索来自角色认知局限（角色只能看到自己看到的）

### 技法二：说将要做但不说结果

- 展示计划的逻辑，让读者觉得靠谱
- 同时暗示不确定性，让读者担心翻车
- 读者此时两种可能都觉得有趣（成功或失败都有看点）

### 技法三：在最后一刻兑现

```
期待建立 → 小挫败 → 再尝试 → 再挫败 → 绝望 → 意外兑现
读者：「能成吗？」→「果然不成」→「再试试」→「算了」→「卧槽！」
```

### 风险控制

- 一条线索从给出到兑现不超过 2000 字无进展
- 一章最多钓 2-3 条线（太多 → 读者注意力分散）
- 线索太密 → 读者猜出结局；线索太少 → 读者觉得被耍

## 产物形态与调用 SOP（NEW-W11 修复补充）

### 调用产物形态

| 调用时机 | 产物形态 | Writer 使用方式 |
|---------|---------|---------------|
| **章首钩子 beat** | **3 个候选钩子**——基于 beat.function + 上章章尾，输出 3 种不同类型的开场（异常/悬念/动作/声音/情绪） | Writer 选 1 个套用，或融合多个元素 |
| **章中钓胃口 beat** | **2 个钓胃口线**——给当前场景增加 1-2 个未解答的子问题 | Writer 选 1-2 个嵌入到当前 beat |
| **章尾钩子 beat** | **不输出产物**——章尾动力由 `emotion-payoff` skill 负责（避免与 emotion-payoff「章尾动力」重复） | 见 emotion-payoff「章尾 5 种形态」 |

### 调用 SOP（3 步）

1. **提取输入**：`current_beat.function`（必须含 hook 标记）+ `next_beat_starter` + 上章 `chapter_end`
2. **输出产物**：按上表产物形态生成候选
3. **Writer 套用**：在 beat 起草时把候选融入正文，不强制全用

### 阈值（NEW-W12 修复补充）

| 阈值 | 数字 | 备注 |
|------|------|------|
| 章首钩子必须出现在前 | 200 字 | 超过 200 字还没钩子 → 读者已经划走 |
| 章首反常密度 | ≥ 1 个反常点 | 反常 = 系统通知/异常数值/不合理现象/有冲击的对话 |
| 章中钓胃口 | 每 1000 字 1 个子问题 | 太密读者疲劳，太疏读者无期待 |
| 章尾钩子落位 | 倒数 50-100 字 | 不要在章末 200 字以外就停了——给读者知道"这是结尾"的信号 |

## 品类适配（番茄系统爽文）

- 章首 500 字必须有「反常」——系统通知/任务弹窗/异常数值/不合理的现象
- 章中钓胃口：用「任务进度」和「隐藏奖励」作为天然信息缺口
- 章尾：新任务发布 / 任务升级 / 隐藏条件触发 是最直接的翻页动力
