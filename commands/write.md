# /novel-studio:write

写指定章节。**不直接动笔**——先分析当前故事状态，和你讨论本章方向，确认后再启动流水线。

## 核心原则

- **先分析后动笔**：每次写之前先报告故事当前状态，防止脱节
- **你来定方向**：生成 2-3 个发展选项供选择，你也可以自己提
- **确认即锁定**：方向确认后流水线自动流转，中间不打断
- **剧情过载自动分章**：超过一章承载力自动建议拆分

## 用法

```
/novel-studio:write <章节号>
/novel-studio:write next          # 写下一章（自动计算章节号）
/novel-studio:write               # 等同于 /novel-studio:write next
```

## 对话流程

### 第一步：状态回顾

每次写新章节前，先报告当前状态，让你知道故事"现在在哪"：

```
📖 当前状态（第 N-1 章结束时）：

   上一章发生了什么：[一句话梗概]
   主角处境：[当前位置/状态/压力]
   活跃伏笔：[列出正在发展的伏笔]
   读者最关心的问题：[列出待解答问题]
   章尾情绪：[上一章给读者留下的感觉]

你想接着写第 N 章，对吗？
```

**这个时候你可以介入**——如果觉得状态回顾有什么不对，或者你想先调整方向，直接说。

### 第二步：方向探索

如果你没有事先给出本章的具体方案，生成 2-3 个发展方向选项。

**生成选项前先问一句**：

```
在我想方案之前——这一章你有没有特别想写的东西？
某个场景、某段对话、某种感觉？
还是完全交给我来想？

（你可以说得模糊，不一定要完整的方案）
```

等待用户回答。如果有具体想法，基于用户的想法生成选项；如果没有，基于当前故事状态生成。

### 选项格式

每个选项保持简洁——不要写 500 字的小作文：

```
💡 第 N 章发展方向：

   选项 A：[方向名]
   ───────────
   这一章的核心是：[一句话]
   关键事件：[2-3 个节点]
   章尾感觉：[读者读完后最想知道/最在意的]
   ✅ [一个优势]  ⚠️ [一个风险]

   选项 B：[方向名]
   ───────────
   这一章的核心是：[一句话]
   关键事件：[2-3 个节点]
   章尾感觉：[读者读完后最想知道/最在意的]
   ✅ [一个优势]  ⚠️ [一个风险]

   选项 C：[方向名]
   ───────────
   这一章的核心是：[一句话]
   关键事件：[2-3 个节点]
   章尾感觉：[读者读完后最想知道/最在意的]
   ✅ [一个优势]  ⚠️ [一个风险]

你可以单选，也可以混合（比如 A 的主体 + C 的章尾），或者提出你自己的方案。
```

### 第三步：剧情量评估

用户确认方向后，评估字数：

```
预估本章：约 XXXX 字（目标 2000 字，范围 1600-2400）
```

如果预估超过 3000 字或关键事件 > 5 个：

```
⚠️ 这一章的剧情量比较大，预估约 XXXX 字。

建议拆成两章：

   第 N 章：[前章方向] — 约 XXXX 字
   章尾落点：[前章落点]

   第 N+1 章：[后章方向] — 约 XXXX 字
   章尾落点：[后章落点]

你的想法？
- 同意拆分：先写第 N 章，第 N+1 章排入队列
- 不拆分：压缩剧情，我帮你删减到 ~2000 字
- 你有别的想法
```

### 第四步：启动流水线

用户确认后，启动自动流转：

```
✅ 第 N 章方向确认 → 启动流水线

📋 设计故事契约...
🎬 编排场景...
✍️ 写作中...
🔍 质量检查...
```

流水线中途如果 Critic 判定需要返修，**自动处理**，不需要用户介入。只报告结果：

```
✅ 第 N 章完成（XXXX 字）
   质量：通过 / 修复后通过（如果修过则说明修了什么）
```

## 快速通道

如果你一上来就给出了非常具体完整的本章方案（剧情路径 + 关键事件 + 章尾落点），一句话确认后直接启动流水线。

## 断点恢复

如果上次 `/novel-studio:write` 中断了，重新执行时自动从断点继续。

## 反模式（禁止）

- ❌ 用户没确认方向就启动流水线
- ❌ 生成的选项每个都是 300 字小作文
- ❌ 用户说了自己的想法，你却忽略并给出完全无关的选项
- ❌ 发现剧情过载时自行删减事件而不告知用户
