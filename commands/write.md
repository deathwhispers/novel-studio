# /novel-studio:write

写指定章节。自动运行完整 5 阶段流水线。

## 用法

```
/novel-studio:write <章节号>
/novel-studio:write next          # 写下一章（自动计算章节号）
/novel-studio:write               # 等同于 /novel-studio:write next
```

## 执行流程

1. **Orchestrator** 分析当前故事状态（上一章内容、活跃伏笔、角色压力、读者疑问）
2. **发展方向探索** — 生成 2-3 个选项供选择：
   - 每个选项包含：方向、一句话梗概、关键事件、章尾落点、优劣分析
   - 用户可直接选择、混合方案、或提出自己的方向
3. **Director** 设计 Story Contract（本章功能 + 信息释放 + 禁止触碰）
4. **ScenePlanner** 设计 Scene Contract（每场景五拍骨架）
5. **Writer** 写正文（在约束内连续起草）
6. **Critic** 5 Checker 质量验收
7. **StateManager** 更新所有状态（通过后）

## 示例

```
/novel-studio:write 10

📖 正在分析故事当前状态…
   上一章：主角利用能力漏洞通过了系统的苛刻测试，系统给出了「创造性使用」的评价
   活跃伏笔：玉佩来源（thr-001）、神秘配角身份（thr-003）
   读者最关心：系统和神秘组织的关系、玉佩为什么对主角的能力有反应

💡 第 10 章发展方向：

   【选项 A】能力试刀 · 推进
   ─────────────────────────────
   主角首次用新能力解决一个实际问题——
   系统发布了一个限时任务：在人群中找到并救出一个被追杀的人。
   主角必须在不暴露系统的前提下完成救援。
   章尾落点：被救的人认出了主角，但主角从未见过他。
   ✅ 优势：兑现上一章的「能力获得」、自然推进主线、引入新角色
   ⚠️  风险：与上一章同为「推进」功能，节奏可能偏紧

   【选项 B】代价浮现 · 揭示
   ─────────────────────────────
   主角在使用新能力后身体出现异常——系统隐瞒了能力的副作用。
   被迫在虚弱状态下应对一个日常冲突（如宗门考核/同学挑衅）。
   章尾落点：系统承认代价存在，但声称「这是必要的交换」。
   ✅ 优势：深化系统的人设（并非无偿帮助）、增加主角困境、引出系列悬念
   ⚠️  风险：读者刚看到主角获得能力就付出代价，可能影响爽感

   【选项 C】暗流涌动 · 过渡 + 铺垫
   ─────────────────────────────
   主角回归日常，但注意到了几个异常：有人跟踪他、玉佩持续发烫、
   系统发布了从未见过的任务类型。过渡为主，铺垫下一段高潮。
   章尾落点：主角主动调查跟踪者，发现对方身上有和他一样的系统标记。
   ✅ 优势：调整节奏、多线铺垫、章尾钩子极强
   ⚠️  风险：可能缺乏足够的「本章满足感」，需要至少一个爽点

💬 你想选哪个方向？也可以混合方案（如 A 的主体 + C 的章尾钩子）。

→ 选 B，但把代价写得轻一点，主要是暗示而不是真的削弱主角

✅ 方向已确认 → 启动流水线
   Director 正在设计 Story Contract…
```

## 快速通道

如果用户给出了完整的章节方案（剧情路径 + 爽点方向 + 关键场景）→ Orchestrator 一句话确认后直接启动流水线，跳过确认轮。

## 断点恢复

如果上一次 `/novel-studio:write` 未完成（中断/异常）→ 重新执行时自动从断点继续。例如 Writer 写到一半中断 → 输入 `/novel-studio:write 10` → 从 NEED_DRAFT 状态继续 Writer。
