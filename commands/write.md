# /novel-studio:write

写指定章节。**逐段写作，逐段确认**——每段前给你选项，你选了再写，写完给你看，点头了再往下走。

## 核心原则

- **先大纲后动笔**：先确认本章整体走向（大方向），再开始写
- **逐段交付**：每次只写一小段（200-400 字/1-2 个场景节拍），写完就停
- **即时纠偏**：你觉得这一段哪里不对，当场纠正，不等到整章写完才发现跑偏
- **多选项 + 自定义**：每段写之前提供 2-4 个自然推进方向，你选一个或自己描述
- **你推我写**：你选方向（或自定义），我根据你的选择来写

## 用法

```
/novel-studio:write <章节号>
/novel-studio:write next
/novel-studio:write
```

## 完整流程

### 第一阶段：确认本章方向（动笔前）

```
📖 当前状态（第 N-1 章结束时）：

   上一章：[一句话]
   主角处境：[当前状态]
   活跃伏笔：[列出]
   章尾情绪：[感觉]

这一章推进方向，我想了几个：

  A. [方向 A：基于节拍表的自然推进]
     — [一两句话说明会写什么]

  B. [方向 B：另一种可能的走向]
     — [一两句话说明会写什么]

  C. [方向 C：借助活跃伏笔/读者期待的走向]
     — [一两句话说明会写什么]

选哪个？或者你有自己的想法直接说。
```

等待用户选择（或自定义）。然后提炼为本章大纲：

```
好的，基于你选的 [方向 X]，这一章大概是：

   [本章方向：一句话]
   - [节拍 1] → [节拍 2] → [节拍 3] → [章尾落点]
   
   预估约 2000 字，分 5-7 小段逐步写。

方向对吗？要调整的话现在说。
```

用户确认（或不确认、调整）。

### 第二阶段：逐段写作（核心流程）

方向锁定后，逐段写。每段流程：

```
┌─────────────────────────────────────────────┐
│  Step 1：我给出 2-4 个推进选项              │
│          你也可以自定义（「我想写XXX」）      │
│                                             │
│  Step 2：你选一个（或自己描述）              │
│                                             │
│  Step 3：我写这段（200-400 字）              │
│          写完就停，不往下写                   │
│                                             │
│  Step 4：你检查                              │
│          可以纠偏任何内容                    │
│                                             │
│  Step 5：我调整 / 你点头                     │
│          → 回到 Step 1，给出下一段选项       │
│          → 或你说「这段可以了，继续」         │
└─────────────────────────────────────────────┘
```

#### 第一段示例

```
✍️ 开始写第 N 章。第一段从哪切入？

  A. 接上一章结尾 — 直接延续章尾的情绪和场景
  B. 场景切换 — 切到新时间/地点，制造跳跃感
  C. 状态描写 — 从主角的当前状态/心理切入
  D. 事件直入 — 直接扔进一个正在发生的事件

选哪个？或者你自己有个具体的开头画面。
（说「你来定」也可以，我按方向选最合适的）
```

等待用户选择。然后写第一段：

```
✍️ 第 N 章 · 第 1 段：

[200-400 字的正文]

---
这段怎么样？哪里需要调整？
```

#### 纠偏示例

```
→ 主角的反应不太对，他应该更谨慎一点，不会直接冲进去

✅ 明白了。改一下主角的反应：

✍️ 第 N 章 · 第 1 段（修改后）：

[修改后的正文]

---
这样可以吗？
```

#### 下一段选项示例

一段确认后，先给选项再写：

```
这段OK。接下来怎么推？

  A. 继续当前场景 — 顺着刚才的情节深入发展
  B. [基于节拍 2 的推进方向]
     — [一两句话]
  C. [基于当前伏笔/悬念的推进方向]
     — [一两句话]

还是你有别的想法？
```

### 第三阶段：触发方式

每一段确认后，系统给出下一段选项。用户也可以主动跳过选项直接用自然语言驱动：

| 用户说 | 我做什么 |
|--------|---------|
| 「A」「B」「你来定」 | 按所选方向写下一段 |
| 「继续」「接着写」 | 按本章大方向给出选项，确认后写下一段 |
| 「接下来写 [具体场景/对话/事件]」 | 按你说的写下一段 |
| 「这段不对，[具体问题]」 | 修改当前段，不改下一段 |
| 「这段OK，但后面我想 [调整方向]」 | 更新本章方向，按新方向给选项 |
| 「可以了，这章到此结束」 | 收尾，进入整章检查 |

### 第四阶段：整章收尾

用户说「这章可以了」后：

```
✅ 第 N 章初稿完成（约 XXXX 字）

快速检查：
   - 排版：[符合规范 / 有几处调整]
   - 对话标签：[正常 / 建议精简几处]
   - 段落节奏：[有起伏 / 某处建议拆分]

[如果有明显问题，直接列出来]

需要我调整上面这些吗？还是直接锁定？
```

用户确认后，锁定章节。

## 中途调整方向

如果在逐段写作中，你觉得大方向需要调整：

```
→ 等等，我觉得刚才那个方向不太对。换个思路——
    [描述想要的新方向]

✅ 好的，更新方向：

   原方向：[旧方向]
   新方向：[新方向]
   
   已写内容中，[保留部分]，[调整部分]。

接下来按新方向继续。写下一段？
```

## 快速通道

如果你对某一章的走向非常确定，可以说「这一章你来定，直接写完整章」。

这时候一次性写完（保持逐段展示，但不每段停下来等你确认——你说停才停）。

## 反模式（禁止）

- ❌ 用户确认了方向就一次性把整章写完甩出来
- ❌ 每段写得太多（超过 500 字）——小段才能精确控制
- ❌ 用户说「这段不对」但没给方向，你就自己猜着改——先问清楚
- ❌ 用户说「继续」你就全自动跑完剩下的——「继续」= 继续写下一段，不是写完
- ❌ 这段没确认就抢跑写下一段
- ❌ 不给选项直接让用户空想——选项降低决策成本，自定义保留灵活性
