# /novel-studio:revise

修订已完成的章节。**不盲目重写**——先确认范围，再最小改动修复。

## 核心原则

- **最小改动**：只改你说要改的，不动其他的
- **范围协商**：如果发现小改动解决不了问题，会告诉你并建议升级范围
- **改动可追踪**：修复完告诉你改了什么、改了多少字

## 用法

```
/novel-studio:revise <章节号>
```

## 对话流程

### 第一步：了解问题

先问你觉得哪里不对——而不是直接上检查工具：

```
🔧 修订第 N 章。你想改什么？

可以直接描述读完后不满意的地方，比如：
- 「场景 2 的对话太生硬了」
- 「感觉结尾很拖沓」
- 「角色 XX 在这章不太对」
- 「AI 味很重，帮我过一遍」
- 「整章都不满意，想重写」
- 或者你看到的 check 报告里指出的问题
```

等待用户回答。

### 第二步：判断范围（内部决策）

根据用户描述，判断修订范围并**告知用户**：

| 用户描述的 | 修订范围 | 说明 |
|-----------|---------|------|
| 「改几处具体的」「对话/描写修改」 | 局部修复 | 只改标记位置，不动其他 |
| 「AI 味太重」 | 去味 | 只修 AI 味关键词，不动剧情结构 |
| 「节奏/场景结构不对」 | 场景重设 | 重排场景但不改剧情方向 |
| 「整章不满意」「重写」 | 全文重写 | 完整重新走流水线 |

```
我的判断是：[修订范围]——[用一句话解释为什么]。

这个范围意味着：
- 会动的：[哪些内容会被修改]
- 不会动的：[哪些内容保持不变]

可以吗？或者你觉得力度不够/太大了？
```

### 第三步：执行修复

确认范围后执行修复。完成后简洁报告：

```
✅ 第 N 章修复完成

   改动：[关键改动的一两句描述]
   字数：[原字数] → [新字数]（[变化百分比]）
   复查：[通过 / 修复后通过]
```

### 升级机制

如果修复过程中发现小范围改动不够：

```
⚠️ 修复过程中发现 [具体问题]：

   原本计划只修 [原范围]，但 [问题] 涉及到了 [更大范围]。
   
   建议升级到 [新范围]。你同意吗？
```

等待用户确认后再升级。

## 修订范围详情

### 局部修复

只修改用户指出的问题位置。不改动未标记的段落。
如果修复牵涉超过全文 30%，自动建议升级为场景重设。

### 去味

全文搜索 AI 味关键词，逐个修复。不改剧情、结构、角色。
参照 `references/de-flavor-techniques.md` 执行修复。

### 场景重设

保持 Story Contract（本章核心功能）不变，
重新设计场景结构和节奏。
Director 不参与（不重新决定本章要讲什么）。

### 全文重写

等同于 `/novel-studio:write N`，完整重新走流水线。
但因为上一章已有，会基于上一章的结尾重新设计。

## 强制规则

- 修订后字数波动不超过 ±20%（除非你要求扩写/缩写）
- 修订不能改变硬规则（力量等级、角色关系等已确定的事）
- 修订不能新增未授权的信息
- 修复引出新问题 → 自动告知并建议升级范围

## 反模式（禁止）

- ❌ 用户说了不满意的点，你却跑全量检查然后按检查报告改
- ❌ 小修小补的问题你却建议全文重写
- ❌ 修改范围超出用户授权——比如他说修对话，你顺手改了剧情
- ❌ 不告知用户就升级修订范围
