# /novel-studio:init

初始化新项目。**不直接生成任何内容**——先对话理解你的创作意图，再按需创建。

## 核心原则

- **先问后建**：不理解你要写什么之前，不创建任何文件
- **逐步收敛**：每轮聚焦 1-2 个问题，不搞问卷轰炸
- **复述确认**：每轮对话后复述理解，你确认了再进入下一轮
- **按需生成**：对话结束后只创建你需要的内容，不过度生成

## 用法

```
/novel-studio:init
```

## 对话流程（O12 修复：5 轮 → 3 轮）

> **为什么压缩**：原版 5 轮对话对新用户门槛较高，且第一/二轮、第三/五轮存在内容重叠（故事起点 + 核心体验都是创作意图；品类基调 + 篇幅模式都是格式确认）。压缩后 3 轮聚焦**创作意图、主角内核、格式确认**三大核心问题，与 `core/作品核心.md` 的灵魂契约结构对齐。

### 第一轮：创作起点 + 核心体验（双问题并提）

**问题 1（开放）**：你想写的故事是什么？

**问题 2（核心体验）**：你希望读者读完这本书后，心里留下什么感觉？

```
💬 聊聊你想写的故事。

可以不完整、可以只是一些碎片——
比如某个场景、某个人物、某种感觉。
或者你对市面上某类书不满意，想自己写一本不一样的。

同时也想确认一下：
你希望读者读完这本书后，心里留下什么感觉？
（比如：爽、燃、虐、悬疑感、被治愈、想了很多天）

两个问题随便聊聊，不用太正式。
```

等待用户回答。复述理解：

```
我理解的是：
- 你想写一个[用户描述提炼]的故事
- 读者体验的核心是[用户说的感觉]
- 与众不同的点是[如果用户提到了]

对吗？
```

### 第二轮：主角的灵魂

问最关键的几个问题——不是问身份和设定，是问人物的矛盾：

```
聊聊主角吧。不用想名字和设定，就说：

1. 他/她最想要什么？
2. 他/她最怕什么？
3. 这两个之间有什么矛盾？

（比如：最想变强保护所有人，但每次变强都会伤害身边的人）
```

等待用户回答。复述你理解的人物内核，确认。

### 第三轮：品类基调 + 篇幅模式（格式确认）

**先给判断和建议**，再让用户确认或修正：

```
从你说的来看，天然适合 [品类建议]——

基调我想确认一下：
  是偏 [严肃/轻松/热血/黑暗/搞笑] 的？
  还是想混合？比如 [具体例子]。

篇幅与模式：
  推荐篇幅：[根据内容推断短篇/中篇/长篇/超长篇]
  推荐模式：[商业连载 / 类型长篇]

你看这样合适吗？
```

等待用户确认或修正。

### 收尾：基于对话生成项目

用户确认所有内容后，**才**开始创建文件：

```
✅ 聊清楚了。基于我们的对话，我整理一下：

   书名建议：[如果用户提到了]
   品类：[确认的品类]
   核心体验：[确认的读者感受]
   主角内核：想要[X]，害怕[Y]，矛盾是[Z]
   篇幅/模式：[确认的篇幅和模式]

现在创建项目骨架——
只会创建和上面这些直接相关的文件，
不确定的标注「待确认」，后面 /novel-studio:world 再补。
```

然后执行 workflow：Architect 创建骨架 → StateManager 初始化状态。

```
✅ 项目初始化完成！

📁 已创建：
   core/作品核心.md
   setting/（硬规则 + 主角档案 + 世界观 + 力量体系）

🎯 下一步建议：
   1. /novel-studio:world   — 继续完善世界观和角色设定
   2. /novel-studio:outline — 设计故事大纲（多线结构/分卷/节奏/伏笔）
   3. /novel-studio:write 1 — 直接开始写第一章
```

## 快速通道

如果你一上来就给出了非常完整的信息（故事概念 + 主角 + 品类 + 篇幅），我会用自己的话复述一遍，确认无误后直接创建项目，跳过逐轮对话。
